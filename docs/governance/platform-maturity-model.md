# Platform Maturity Model

## Purpose

Track evidence-based maturity beyond feature count.

## Levels

- **0 — Undefined:** no agreed approach.
- **1 — Documented:** intent and ownership are defined.
- **2 — Implemented:** a usable baseline exists.
- **3 — Verified:** automated checks and operational evidence exist.
- **4 — Managed:** metrics, support and upgrade processes are active.
- **5 — Reference:** stable, documented and demonstrated across real applications.

## Dimensions

Architecture, documentation, AI-native readiness, security, privacy, accessibility, testing, observability, performance, governance and developer experience.

## Rules

- Scores must reference concrete evidence.
- Missing evidence remains unknown or incomplete.
- A high score in one dimension does not offset a critical gap in another.
- Releases should publish material maturity changes.
- Epic planning should identify which dimensions it advances.

During Epic 0, architecture, documentation, governance and AI-native readiness target Level 1. Runtime dimensions remain Level 0 until executable code exists.
