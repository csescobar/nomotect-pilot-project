# Documentation Standards

## Required structure

Architectural and module documents should include, when applicable:

1. Purpose
2. Context
3. Decision or contract
4. Examples
5. Security and privacy considerations
6. Extension points
7. Future evolution
8. References

## Rules

- Write repository content in English.
- Use the project ubiquitous language.
- Distinguish implemented behavior from planned behavior.
- Prefer links to one source of truth over duplicated text.
- Include executable or testable examples when code exists.
- Update affected diagrams, manifests and AI context in the same pull request.
- Record uncertainty and known limitations explicitly.

Documentation is part of the public API and follows the same review expectations as code.
