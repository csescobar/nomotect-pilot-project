# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues. Use GitHub private vulnerability reporting when enabled. Until that channel is available, contact the maintainer privately through the security contact published on the repository profile.

Reports should include affected component, reproduction steps, impact, prerequisites and any suggested mitigation. Do not access data that is not yours or disrupt shared systems while testing.

## Response objectives

The project will acknowledge valid reports, assess severity, coordinate remediation and publish an advisory when appropriate. Response times are goals rather than contractual guarantees during the pre-1.0 phase.

## Supported versions

Before 1.0, only the latest released minor line is expected to receive security fixes. The support matrix will be published with the first executable release.

## Security principles

- Secure defaults and least privilege
- Server-side authorization and tenant scoping
- Safe handling of secrets and personal data
- Dependency and supply-chain review
- Coordinated disclosure
- Traceable security decisions and tests

This policy does not claim compliance or certification by itself.
